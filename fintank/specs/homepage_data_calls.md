### App entrance point. 

1. The app enters on the home page which makes various backend calls via the urls below. 

 -/`index-performance`, this url calls the `get_index_performance_task`, which makes a call to the cached redis files. The get index performance task makes a call to the `home_index_cache` for the data stored in the redis cache. If the cache is empty it calls the `get_index_performance` method which then populates the cache with updated values. The `IndexReturnsSidePanel` which consumes this data via the `useHomeINdex` Hook only shows a slice of 6 of these. The additional data is there for another function in the front end which consumes the entiure cache data directly anbd displays a performance page. 
 
 
 - The home page also loads the `IndexChartSection` which shows various index time series data. It makes a call to the `IndexCharterCard` whcih uses the hook `useIndexCharter`. This hook calls the `/index-history` which takes an index argument. This api request calls the `get_index_history_task` view which does a view things. It calls the `home:index_chart` redis cahce passing a symbol. If the cache is not populated then the view will call the `get_index_charts` funciton which returns the data bit also populates the cache for later calls. The `get_index_chars` function makes a few bulk calls to the `FMP` api to return the historical time series data. The `FMP Agent` should review this proces for efficinecy and cost. This fucntion is where we would add any new charts we may want to show. 

 - The next component the home page calls is the `SectorPerformanceSection`. This section uses the `useSectorData` hook which makes a request to the `/sector-industry` url passing with it an exchange for which to pull this information. This backend url makes a call to the `get_gainers_losers_task` view. This view puls data from the `home:gainers_losers:v1` cache unless it is not populated at whcih point the view requests the function `get_biggest_gainers_and_losers`. The FMP agent could review this since it is just an FMP API call. 

 - The next section is the `Movers` section which is really where the IndexHeatMap is used. The heat map uses the `useIndexHeatMaps` hook which makes multiple calls to the `/constituent-returns` endpoint. This endpoint takes a `universe` like `sp500` `nas`  etc and calls the `get_constituent_returns` function. This function calls the `home:universe_constituent_returns` cache  to load the data from the cache, other wise it calls the `get_universe_constiutent_returns` function to load the cache and return the data at the same time. This function calls a `get_heat_map_data` function from the data_getter `GetData()` class.
